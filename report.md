## 3. Принятые решения (Часть 1)
- **`SKIP_FIELDS`:** в множество включено поле `"password"`, чтобы исключить случайную утечку паролей при сериализации и покрыть это тестом.
- **Повторная регистрация в `REGISTRY`:** при повторном объявлении класса с тем же именем запись в `REGISTRY` перезаписывается (`REGISTRY[name] = cls`). Это удобно при перезагрузке модулей и в тестах.
- **Проверка `bool` при ожидании `int`:** в Python `bool` — подкласс `int`, поэтому `isinstance(True, int)` возвращает `True`. В `validate` и `from_dict` булевы значения для полей с аннотацией `int` явно отклоняются через `type(value) is bool`.
- **Обработка `None` и `Optional`:** для обычных аннотаций (`str`, `int`, `Address` и др.) `None` считается ошибкой валидации; при явном использовании `Optional[T]` / `T | None` значение `None` допускается.
- **Защита от циклических ссылок (бонус 7.1):** в `to_dict` ведётся множество `id()` активных объектов текущей ветки рекурсии, что предотвращает `RecursionError` и возвращает маркер `"<circular: ИмяКласса>"`.

## 4. Результаты мини-исследования `__init_subclass__` vs `metaclass`

| Критерий | `SerializableMeta` (метакласс) | `Serializable` (`__init_subclass__`) |
|:---|:---|:---|
| Объём кода | ~10 строк (`class SerializableMeta(type)` + `__new__`) | ~7 строк (`class Serializable` + `__init_subclass__`) |
| Момент срабатывания | Перехватывает **создание** класса (`__new__` до `super().__new__`) | Вызывается **после создания** объекта подкласса |
| Влияние на создание класса | Может модифицировать `namespace` и `bases` до конструирования класса | Работает только с уже созданным классом `cls` (добавляет/проверяет атрибуты постфактум) |
| Совместимость с `dataclass` и наследованием | Требует `metaclass=...`; при множественном наследовании классов с разными метаклассами возможен конфликт метаклассов | Полностью совместим с `@dataclass`, `ABC` и множественным наследованием без конфликта метаклассов |

**Вывод:** Для задач вроде регистрации подклассов и добавления готового метода `to_dict` механизм `__init_subclass__` проще, короче и безопаснее с точки зрения совместимости с другими декораторами и базовыми классами (`dataclass`, `ABC`). Метакласс `SerializableMeta` оправдан в тех случаях, когда требуется изменить `namespace`, отфильтровать атрибуты или провалидировать структуру класса *до* фактического вызова `type.__new__`, либо когда классы не должны иметь общего базового класса в иерархии.
